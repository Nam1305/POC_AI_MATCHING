# Task: Viết script `generate_implies.py` sinh bảng quan hệ skill "IMPLIES" từ Wikidata

## 1. Bối cảnh

Hệ thống chấm điểm CV-JD có 1 bug: JD yêu cầu "JavaScript", CV chỉ ghi "ReactJS" (không ghi tường
minh JavaScript vì ai cũng hiểu biết React là biết JS) → hệ thống đánh trượt (miss) skill này. Cần 1
bảng quan hệ 1 chiều "biết X thì chắc chắn biết Y" (gọi là `IMPLIES`, vd react→javascript,
django→python, spring→java) để dùng cho matching sau này. Bảng này sẽ được sinh tự động từ Wikidata
thay vì viết tay từng dòng.

**Scope của task này CHỈ LÀ viết script sinh ra file dữ liệu tĩnh. Không đụng vào logic chấm điểm
(`scorer.py`, `evaluator.py`) — phần đó sẽ làm ở task khác.**

## 2. Yêu cầu

Viết `scripts/generate_implies.py`:

1. **Input**: danh sách skill canonical, lấy từ `SkillMatcher.ALIASES` trong
   `app/services/scorer.py` (dòng 51-127) — đây là các giá trị (value) trong dict đó, vd "react",
   "django", "spring", "python"... (~80 token, dedupe lại).

2. **Map skill → Wikidata QID**: viết tay 1 dict cố định ngay trong script, map từng skill canonical
   sang đúng Wikidata QID của nó. **Không dùng kết quả đầu tiên của API tìm kiếm 1 cách tự động** —
   phải tự tra và pin cứng, vì tên ngắn/thông dụng dễ bị nhầm sang nghĩa khác (vd search "Angular"
   trên Wikidata ra top-1 là Q28390 = "angle", đơn vị đo góc — phải tự chọn đúng Q28925578 là
   framework). Dùng API `https://www.wikidata.org/w/api.php?action=wbsearchentities&search=<tên>&language=en&format=json`
   để tra cứu, nhưng người viết script phải tự xác nhận từng ID trước khi đưa vào dict.

3. **Query quan hệ**: gọi 1 lần (batch) tới SPARQL endpoint `https://query.wikidata.org/sparql`,
   dùng `VALUES ?item { wd:Qxxx wd:Qyyy ... }` để đưa tất cả QID vào cùng 1 query, lấy property
   **P277** ("programmed in"). Ví dụ query:
   ```sparql
   SELECT ?itemLabel ?valueLabel WHERE {
     VALUES ?item { wd:Q19399674 wd:Q42406 ... }
     ?item wdt:P277 ?value .
     SERVICE wikibase:label { bd:serviceParam wikibase:language "en". }
   }
   ```
   **Chỉ lấy P277. Không lấy P1547 ("depends on software")** — property này trả về hàng chục
   dependency phụ vô nghĩa với bài toán skill-matching (vd thư viện spaCy sẽ kéo theo "murmurhash",
   "thinc", "wasabi"... — không ai liệt kê những cái đó là 1 skill trong CV).

4. **Resolve kết quả về đúng skill canonical**: SPARQL trả về QID hoặc label của "value" (ngôn ngữ
   nền) — phải map ngược lại về đúng token đã dùng trong `ALIASES` (vd Wikidata trả "JavaScript" →
   phải ghi là `"javascript"`, không phải `"JavaScript"` hay để nguyên QID).

5. **Transitive chain**: 1 vài framework chỉ có quan hệ trực tiếp với framework khác chứ không với
   ngôn ngữ (vd Next.js → React, không có Next.js → JavaScript trực tiếp) → cần nối lại thành chain
   nhiều tầng nếu Wikidata không cho quan hệ trực tiếp tới ngôn ngữ gốc.

6. **Output**: ghi ra file `app/services/skill_implies.py`:
   ```python
   # Auto-generated by scripts/generate_implies.py — DO NOT EDIT BY HAND.
   # Source: Wikidata property P277 ("programmed in"). Regenerate khi cần cập nhật.
   IMPLIES: dict[str, set[str]] = {
       "react": {"javascript"},
       "vue": {"javascript", "typescript"},
       "nextjs": {"react", "javascript"},
       ...
   }
   ```

## 3. Rủi ro / lưu ý kỹ thuật

- **Rate limit**: Wikidata trả lỗi "too many requests" nếu gọi API liên tục không delay. Ưu tiên 1
  batch SPARQL query duy nhất thay vì gọi lẻ từng skill; nếu vẫn cần gọi `wbsearchentities` nhiều
  lần lúc tra QID, thêm `sleep` giữa các lần gọi (~1-2s).
- **Một số skill không có QID phù hợp trên Wikidata** (đã gặp: ASP.NET bản cũ, .NET Framework,
  LangChain, mlflow — không có property P277 riêng). Với các skill này, để trống hoặc note lại
  trong script, không bắt buộc phải có đủ 100%.
- **Một số Wikidata item thiếu label tiếng Anh** dù entity vẫn tồn tại đúng — nếu label rỗng, dùng
  bảng map QID → tên đã tự tra tay ở bước 2, không loại bỏ record.
- Script chỉ chạy offline/tay (hoặc CI định kỳ), **không được import/gọi trong `scorer.py` hay
  `evaluator.py`** — 2 file đó sau này chỉ đọc `skill_implies.py` như 1 dict tĩnh, không có network
  call lúc chấm điểm.
